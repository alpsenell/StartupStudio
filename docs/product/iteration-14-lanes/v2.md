## What I built

### C5 prep — the desk rows carry their deadlines (`DeskCard.swift`)

U1 found the Business badge reading 0 on every fixture because the rows
that matter had `daysLeft == nil` (its follow-up 1). Two of them have a
real date in the state, and now carry it:

- **The reporter's twenty minutes:** until the build the press want ships
  (`shipETAs`, the first case of `interviewableProductID`), or until a
  shipped build leaves its launch week (the second case).
- **A rival's price war:** the answer window the decision sheet's question
  closes on (`RivalMarket.answerDeadline`), while the war is unanswered. An
  answered war, or one past its window, is an open state again (undated).

Booms and crashes, the loan and board pressure stay undated: they are news
and states, not questions with a clock.

**Side effect, on V1's ground.** Life's Fortnight (`Agenda.swift`) already
lists every *dated* desk row, so the reporter now appears there too, on the
build's ship day, next to "X ships". On the agenda snapshot it pushes the
third row (an earn-out review, 2 days out) behind "All 14 days" (see
Re-pins and follow-up 9).

### C5 — one inbox (`Components/WaitingSheet.swift`, new)

**The +N on the rail opens "Waiting on you"**, a single sheet listing every
open question, each with its deadline and a button that goes where the
rail's would. The journal stays on HQ as the log, and sits at the foot of
the sheet.

`WaitingList` is derived, never stored. It reads four sources that already
existed:

  (`laneNotices`, `fallbackTip`, `laneRoute`), J1's hooks inside them and

- **The shop's anti-nag rule holds:** no source above can hold a purchase.

### C10 — the weekly report can be reopened (`GameShell`, V2 region)

A closed report used to be gone. The shell now keeps this session's reports
by week (`reportsByWeek`), and after a relaunch rebuilds the latest closed
week from the state, which is what opening an unread report late has always
done. Reopening pauses behind the sheet and "Next week" resumes, like the
rail's open. `WeeklyReport` and its tests are untouched.

- **From the rail:** the +N sheet's "The log" group has "Week N report".
- **The hook V3's journal week row calls.** V3 lands first with
  `JournalCard.reopenReport` as `nil // V3: call V2's reopen here`, and its
  `reportOpener(for:)` offers the button on every closed week
  (`week <= day / 7`). This worktree does not have V3's file, so the PM
  applies this at merge. It replaces the two members inside V3's markers in
  `HQ/JournalCard.swift`; `WeekGroup` is untouched:

  ```swift
  private func reportOpener(for week: Int) -> ((Int) -> Void)? {
      // V2: only a week the shell can show draws as a button.
      guard GameShell.shared.canReopenReport(week: week, engine: engine) else { return nil }
      return reopenReport
  }

  private var reopenReport: ((Int) -> Void)? {
      { week in GameShell.shared.reopenWeeklyReport(engine: engine, week: week) }
  }
  ```

  `GameShell.shared` is the root's shell (`AppRootView` holds
  `@State private var shell = GameShell.shared`), so no environment property
  is needed. Weeks are the journal's own `JournalEntry.week`, which is the
  report's numbering. The root's existing report presenter shows it; V3
  needs no presenter of its own.
- **No side effects on the report loop** (V3's concern about
  `openWeeklyReport`). A week built this session reopens as the exact
  `WeeklyReport` value that was shown then. The latest closed week, if it
  is not in memory (after a relaunch), is built once from the state, the
  way a late-opened unread report always has been. Neither path touches
  the delta baselines (`previousMorale`, `previousMeters`) or
  `weeklyReportManualOpens`. The one exception is a week whose report is
  still unread (`pendingReportWeek`): that is its first reading, so it
  goes through `openWeeklyReport` exactly as the rail's chip does.
- `reopenWeeklyReport(engine:week:)` returns `false` and does nothing for a
  week it cannot show; `week: nil` means the latest closed week. Weeks
  older than this session's, after a relaunch, are not reopenable (see
  follow-up 5), and the guard above keeps their headings plain.
- Debug: `-autoReopenReport` (`after/campus-report-reopened.png`: week 128
  at day 900).

## Follow-ups

1. **V3's journal week row**: the hook above. Nothing on HQ calls it yet
   (`JournalCard` is V3's).
2. **J5's countdown row's Answer button** (not mine, noticed while
   building the inbox): `AnnounceRail`'s rows have no queue answer and no
   lane route, so the rail's Answer on "X ships …" falls through to
   `recallDeferredChoice()`, which brings back whatever story beat was put
   off, or does nothing. It wants `.announce` from the `laneRoute` seam.
   The inbox leaves the countdown out.
3. **The rail's +N number is the rail's swipe count**, not the inbox's
   count (it still says how many other notices a swipe reaches). If the
   owner wants the counter to be the inbox's number, it is one line in
   `NoticeRail.row(for:queued:)`, and `rail_queue` re-pins.
4. **The product detail page keeps its own pace control**, and Life's work
   card too until V1's read-only line lands. The audit's "1 + 5" becomes
   1 on Products plus the detail page when it is pushed.
5. **`reportsByWeek` is per launch.** After a relaunch only the latest
   closed week can be reopened. Keeping older weeks would need them in the
   save, which is an engine change.
6. **Weekly closes are matched by their text** (`"Week "…" closed. "`, U1's
   rule). If the office's close copy changes in `EventCopy`, the filter
   must change with it.
7. **`make strings`**: new keys in `WaitingSheet.swift` (headings, the
   summary, the deadline words, "Week N report", "Journal"), the desk
   card's "N more waiting on you", the Team pace card, the build card's
   "Team pace, set at the top", the phone's two close lines, and the
   renamed papers strings.
8. **Merge notes.** `AppRootView.swift`: a `@State` and the sheet with its
   helpers inside V2 markers, plus two one-line guards (in
   `weeklyReportPresented` and `pendingDecision`). `GameShell.swift`: a V2
   block after J6's, one line in `openWeeklyReport`, two in `rebase`.
   `BusinessScreen.swift`: the `DeskCard` call wrapped in V2 markers and a
   shell property. `DebugLaunch.swift`: two flags in the V2 static region.
   `NoticeRail.swift`: `queueNotices` now calls `static queueRows`
   (J6's body moved, unchanged) and the counter's target.

9. **The Fortnight now carries the reporter** on the day the build
   ships, which says one date twice ("X ships" and "A reporter wants
   twenty minutes…"). If V1 or the owner want one row, the fix is in
   `Agenda.swift` (skip `pitch-journalist` when that build's ship row is
   present). It was not done here because it is V1's card.
10. **The inbox has no screen-reader rotor or tap-through test.** `simctl`
    cannot tap, so the row buttons' routes were checked in code against
    the rail's (`runWaitingPick` mirrors `deferredRow`'s button). They
    were not tapped on the simulator.
