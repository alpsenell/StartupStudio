# N2 — People you can mess with

*Iteration 11, wave one. Branch `n2-people`, cut from `scaffold-11`.*

## What this lane is

Every person in the game — the partner, each child, each friend, each
employee, each contact in the book, each rival founder — now has a
BitLife-sized menu instead of three buttons. Twenty-three interactions
across four shelves (nice, mean, money, serious), each with a cost, a
cooldown, a visible bar that moves, a percentage that is the percentage
the engine actually rolls against, and a line back in the game's voice.
The old people actions have not moved: they are listed in the same menu,
next to the new ones, dispatching exactly the actions they always did.

A rival with a grudge becomes a personal nemesis you can taunt, sabotage
or offer to bury it with.

## The interaction table

Deltas are for the default target kind; a cell in **overrides** replaces
them for that kind. A rival's bar is `grudge`, where *up* is worse for you,
so the mean rows are positive there. `baseChance` is before the founder's
conversation attribute (±0.30 across the 0…100 range) and the current bar
(±0.20) are read into it, clamped to 5…95%.

The money rows only move the wallet the way they promise: a *positive*
wallet cost (a gift, a loan) is always paid; a *negative* one (asking for
money) only arrives on a good roll, which is why the button says
"+$2,000 if they say yes".

Beyond the bar, an interaction also moves the founder: an evening row is
energy −4 / relationships +3 / mood +3 on a good roll; a nice row landing
is mood +1.5; a mean row going wrong is mood −2. An employee's `morale`
follows their `founderBond` at half weight, so treating somebody badly is
felt in the sprint as well as in the relationship.

## Identity at the default

- `InteractionState` encodes `{}` untouched, so `GameState` omits the slot;
  every field is written only once it has something to say and the cooldown
  map encodes as a sorted array.
- `Rival.grudge` decodes-if-present and encodes only when non-zero, so a
  rival nobody has annoyed writes the bytes it wrote before.
- The 33 `people_*` life events are every one of them gated on a narrative
  flag this lane raises (`people_meddler`, `people_cruel`, `people_affair`,
  `people_nemesis`, `people_estranged`). A run that never opens a menu never
  raises one, so the eligible event pool — and therefore the whole weighted
  draw — is bit-for-bit what it was.
- No new draws on a tick: `socialRNG` is only touched inside `perform`,
  which is only ever reached from a player's tap.
- `TycoonEngine` stayed at 943 tests with no re-pin, which is the proof.

## One thing worth knowing about friends

L4's friend roster is **lazy**: it is a pure function of the seed until the
founder does something worth remembering, at which point
`FriendSystem.materialise` writes it into state. Read naively, a friend's
menu on a run that has never called anybody would have said "not in your
life any more" about a real friend. So `interactionBar`, `interactionName`,
`interactionSeed` and `interactionOdds` all take an optional
`content: ContentCatalog?` and go through `friendRoster(content:)` when
they have one (every call site in the app passes `engine.content`), and
`perform` materialises the roster *after* the blocker check, so a refused
row still changes nothing at all.

## `talkToContact` and `-autoRoute`

- `-autoRoute people` opens the partner's menu, falling through to the first
  child, friend or employee on a run with no partner.
- `-autoPeopleKind <partner|child|friend|employee|contact|rival>` picks which
  of the six menus that route opens on.
- `-autoRoute peopleTeam` opens the Team tab's manage sheet on the first
  person on the roster, which is the other door onto the employee menu.
- Two screenshot-only flags, both DEBUG and both documented in
  `DebugLaunch`: `-autoInteract <id>` performs one interaction, once,
  through the ordinary reducer (a simulator cannot tap a row), and
  `-autoPeopleGroup <shelf>` draws one shelf so a pass can photograph the
  mean half of a twenty-row menu without scrolling. Neither is a back door
  into state.

## Deviations from the brief

1. **No new `GameEvent` cases.** The brief's scaffold left an N2 region in
   `GameEvent`; I left it empty and the region is still there for wave two.
   `EventCopy.swift` and `EventPresenter.swift` have no N2 marker and are
   not on my ownership list, so a new case would have fallen through to
   `@unknown default` and printed "Something happened" in the journal —
   worse than no line at all. The outcome is carried by the phone thread,
   the child's ledger, the outcome paper and `InteractionState.lastOutcome`
   instead. `breakUp` emits the *existing* `.breakup(day:)`, which already
   has copy. **Follow-up:** whoever owns `EventCopy` next can add
   `interactionPerformed` copy and I will emit it.
2. **Child memory kinds.** `ChildMemoryKind` is L3's enum in
   `Childhood.swift`, which I do not own and which has no marker, so a
   people-menu memory is written with the raw kinds `people_warm` /
   `people_sour`. `MemoryRow` renders an unknown kind with a circle in the
   accent colour rather than a themed icon, so the ledger reads fine but a
   sour memory is not tinted red. **Follow-up for L3 or the PM:** two cases
   on `ChildMemoryKind` and the icons come right.
3. **`propose` is `advanceRelationship`**, as the brief asked; it is a
   legacy row in the serious shelf rather than a JSON interaction, because
   the ladder's gate lives in `LifeSystem` and duplicating it in content
   would have given the menu a second, divergent answer.
4. **`talkToContact`** is not in the menu. Its three conversation topics
   only exist inside an open networking room and are metered by
   `conversationsLeft`; a row that says "only at an event" on every menu
   pass is noise, and `ContactSheet` already shows them where they work.
   The contact's menu carries the new rows instead.
5. **The nemesis strip is on the profile but photographed from the menu.**
   `PeopleNemesisCard` sits between the history card and the deal card on
   `RivalProfileScreen`; it is below the fold on a phone and a simulator
   cannot scroll, so screenshot 06 is the rival's own menu — same rows,
   same grudge bar, same outcome paper. The card builds and is reachable.
6. **No `Balance.json` key.** Rule 9 only bites if a lane adds a
   `BalanceConfig+X.swift`; this lane's numbers are in `InteractionTuning`
   for the reason given above, so `Balance.json` is untouched.

## Seams wave two's family drama (W2) should use

- **The affair flag.** `state.interactions.affairContactID` (the contact),
  `affairSinceDay` (when it started) and `affairDiscoveredDay` (nil while it
  is still secret), with `hasAffair` and `affairIsSecret` as the two
  predicates. The narrative flag `people_affair` is raised the moment it
  starts, so a `people_`- or `family_`-prefixed life event can gate on it
  with `requires.flagsAll`. **W2 owns discovery**: set
  `affairDiscoveredDay`, and the four `people_*` affair events already in
  `LifeEvents.json` (`people_two_phones`, `people_alibi_rehearsal`,
  `people_a_friend_noticed`, `people_calendar_collision`,
  `people_expensive_dinner_receipt`) are the slow burn before it.
- **`breakUp`.** `GameAction.breakUp` and
  `InteractionSystem.breakUp(state:balance:content:)` are the deliberate
  end of a relationship: stage to `.single`, partner cleared, affection to
  zero, the diary's partner dates removed through
  `FamilyCalendar.partnerLeft`, the mood penalty applied, and the existing
  `.breakup(day:)` event emitted. It deliberately does **not** touch the
  home, the children or any assets — that split is W2's, and calling
  `InteractionSystem.breakUp` first and then dividing the estate is the
  intended shape. `people_estranged` is raised, and the six
  `people_*` estrangement events read it.
- Also there for W2: `disownedChildIDs`, `firedWithCauseIDs` (N5's harshest
  response routes through `.fireWithCause`, and the alumnus entry is closed
  as `.lost` so the boomerang never returns them), and `Rival.grudge` for
  W3's espionage.
