# M2 — The pitch room

Branch `m2-pitchroom`, from `scaffold-10`. No merge, no push.

## What it is

A term sheet, a contract offer, a launch-week interview and a quarterly
board review were each a card with two buttons on it. Each now carries a
*Talk first* invitation that opens a short conversation in the networking
floor's grammar — small talk, talk shop, ask about them, pitch — with one
person at a table. What is said moves the paperwork, and the accept or
decline underneath is exactly the button it always was.

The whole feature hangs off one invariant: **warmth zero is the game that
shipped**. Every revision is written as `term × (1 + warmth/100 × span)`
or `+ warmth × k`, so a run in which nobody sits down cannot be changed by
any number in the balance block. `state.pitch` is `nil` until the player
presses the button and is put back to `nil` the moment there is nothing
left to remember, so the save of a run that never pitched is the save it
always was.

## What I built

### Engine

- **`PitchRoom.swift`** (reshaped from the scaffold's stub). Types:
  `PitchCounterpart` (investor / client / journalist / board),
  `PitchBand` (hostile / cool / even / warm / sold), `PitchSession`,
  `PitchRecord`, `PitchState` (hand-written Codable: sorted `spent`,
  omits every empty field), and the `PitchRoom` namespace — the pure half.
  `PitchRoom.swing(warmth, span:)` is `1 + warmth/100 × span`; both
  `revised(_:warmth:balance:)` overloads, `pressNotch`, `hypeDelta` and
  `pressureDelta` go through it, and every one of them is an identity at
  warmth 0. Also `PitchRoom.read(...)` — the consequence line on each
  exchange button (rule 7) — and the closing/summary copy.
  At the bottom, three public queries on `GameState`
  (`pitchSubject`, `interviewableProductID`, `pitchBlocker`) so a card in
  the app can ask "is there anybody in that chair, and if not, why not"
  without reaching into a system.
- **`Systems/PitchSystem.swift`** (new). `open` / `say` / `leave` /
  `run`. `run` is registered in the reducer's M2 region and returns
  immediately when `state.pitch == nil`, which is every bot run.
  Draws: opening takes two words from `state.socialRNG` (the want, the
  opener); every exchange takes exactly one, including the two topics that
  cannot fail, so the stream advances identically whatever the player
  says. `rng`/`worldRNG` are never touched. Settling is the only place in
  the lane that writes outside `state.pitch`.
- **`Balance/BalanceConfig+Pitch.swift`** + a `"pitch"` object appended
  after `"sabbatical"` in `Resources/Balance.json` (26 keys, matching the
  Swift defaults exactly). `BalanceConfig.pitch` is an inline default with
  a `decodeIfPresent` shim, so a balance file without the key still loads.
- Marker regions only, in the shared files: three actions
  (`.openPitch`, `.sayInPitch`, `.leavePitch`) in `GameAction.swift`; two
  events (`.pitchOpened`, `.pitchClosed`) in `GameState.swift`;
  `PitchSystem.run` in the reducer's system list and the three handlers in
  its handler switch.

### Content

- **`Pitches.json`** in `TycoonContent/Resources`: four counterparts, four
  openers each, four hidden wants each (name, tell, reveal, the topic it
  favours, the line when the founder hits it), and four land / four miss
  lines per topic — 4 × (4 + 4×6 + 5 closings) ≈ 130 written lines.
- **`PitchCatalog.swift`**: `PitchCatalog`, `PitchCounterpartDef`,
  `PitchWantDef`, `PitchLineSet`, plus `PitchCatalog.fallback` — a terse
  but complete catalog, so a build without the JSON still plays the room.
- `ContentCatalog` gains `pitches: PitchCatalog?` (decode-if-present) and
  `pitchCounterpart(_:)`, which falls back so no caller handles "no
  catalog". All inside marked regions.

### App

- **`Screens/Business/PitchRoom/`** (new, all mine):
  - `PitchRoomSheet` — the sheet: the room on top, the terms and the four
    exchange buttons under it, and the closed state after.
  - `PitchTableView` — the room itself, drawn like `NetworkingFloorView`:
    a per-counterpart gradient, a table slab, a `PixelFigure` standing
    behind it whose seed is an FNV-1a hash of the thing being discussed
    (so the same investor has the same face every time), the last line
    over the table with a green or red border, the tell while the want is
    still hidden, and `PitchWarmthBar` — a bar that fills from the middle
    out, because the centre is the paper as written and both directions
    are real.
  - `PitchTermsCard` — every term as `paper → what it would be if you got
    up now`, computed by calling the same `PitchRoom.revised` the engine
    settles with. At warmth 0 there is one number and no arrow.
  - `PitchInviteButton` — the *Talk first* button plus its own sheet. It
    draws nothing when there is nobody there, and says why in place of the
    button when there is somebody but the room is refused.
- Entry points, each in a marked region: `TermSheetCard` and the board
  card in `InvestorsView.swift`, `ContractOfferCard` in
  `ContractsView.swift`, `PressStripView` in `PressStrip.swift` (with a
  defaulted `engine` so every existing call site draws what it drew), and
  a desk row in `DeskCard.swift` pointing at the war room where the
  interview is offered.
- `Route.pitch` + its tab, `-autoRoute pitch` and my own `-autoPitch
  <counterpart>` / `-autoPitchSay <topics>` in `DebugLaunch.swift`,
  consumed in `BusinessScreen.consumeRoute`'s M2 region.
- `EventCopy` gains lines for the two events; `NewspaperComposer.leadRank`
  gains a marked bump so a *good* journalist pitch takes the front page's
  lead (a conversation that went nowhere gets no boost, so a week the
  player did not engage with ranks exactly as before).

## The bands each counterpart can move

All at full warmth (±100); everything is linear in warmth and exactly
zero at warmth 0.

| Counterpart | Term | Span at full warmth | Balance key |
|---|---|---|---|
| Investor | cheque | ±25% | `investorAmountSpan` 0.25 |
| Investor | their equity | ∓20% (warmth makes it smaller) | `investorEquitySpan` 0.20 |
| Investor | patience | ±30% of the persona's weeks | `investorPatienceSpan` 0.30 |
| Investor | valuation | re-derived from the two above | — |
| Client | fee (and the penalty, pro rata) | ±20% | `clientPayoutSpan` 0.20 |
| Client | deadline | ±25% of the days | `clientDeadlineSpan` 0.25 |
| Client | crew they expect | ∓25% | `clientSkillBarSpan` 0.25 |
| Journalist | one outlet's review | ±20 points (one band), at \|warmth\| ≥ 40 | `pressNotchPoints` 20, `pressNotchWarmth` 40 |
| Journalist | hype before launch | ±12 | `pressHypeSwing` 12 |
| Journalist | front page | the lead, on a warm or sold room | — |
| Board | board pressure | ±12 points, and the review's note | `boardPressureSwing` 12 |

A conversation runs three exchanges, plus one per 40 points of the
founder's conversation attribute, capped at five. A landed exchange is
worth `16 × topic factor × charm` warmth (small talk 0.55, listen 0.45,
talk shop 1.2, pitch 2.0); a miss costs 0.85 of that. Talking shop is
graded on the counterpart's own attribute (finance for the investor and
the board, technical for the client, market sense for the journalist);
the pitch is graded on conversation plus the warmth already in the room.
Aiming at the counterpart's want doubles the topic — but only once the
founder has listened, so listening is a real move rather than flavour.

## Deviations from the brief

1. **No marked regions in `InvestorSystem.swift` or `ContractSystem.swift`.**
   The brief reserved them for "term sheet terms and board review outcome
   from a pitch". Settling writes the revised terms straight back into
   `state.investors.pendingOffer` / `state.contractOffers[i]` /
   `state.investors.boardPressure` instead, so the accept and decline
   paths in those two systems are byte-identical and untouched. That felt
   strictly safer than intercepting them.
2. **The journalist's review notch does not touch `ProductSystem`.**
   `ProductSystem.swift` is M1's file. An interview on a build in
   development books a notch in `PitchState.pressBumps`, and
   `PitchSystem.run` — which runs after every other system in the tick —
   spends it on the tick the product reaches the market, shifting the
   first outlet's score by `pressNotchPoints` and re-picking its blurb
   from `socialRNG`. An interview about a product already on the market
   takes its notch immediately.
3. **`PressStrip.swift` and `WarRoomScreen.swift` are not in M2's
   ownership row**, but the brief's M2 build section names the launch-week
   press strip as an entry point and no other lane owns those files. I
   added two small marked regions: a defaulted `engine` on
   `PressStripView` and the button under the panel (outside it, because
   the panel's own accessibility element ignores its children), and the
   argument at the one call site.
4. **`EventCopy.swift` and `NewspaperComposer.swift`** — the scaffold's
   own comment in `GameState.swift` says the copy for a lane's events
   lives in `EventCopy`, and the brief names "the newspaper's interview
   hook (`App/Sources/Screens/Story`, marked)" as mine. Both are marked
   regions.
5. **`GameEvent.severity` has no M2 case.** Its switch ends in
   `default: .info`, so both events grade `.info` — never interrupting.
   The switch is not in a marked region, so I did not touch it.
6. **The desk row for the interview routes to `.warRoom`, not `.pitch`.**
   The interview is offered under the press strip, where the outlet's name
   is; the desk row is the pointer, not the room.
7. **One extra debug flag beyond the brief's `-autoPitch`:**
   `-autoPitchSay <topic,topic,…>` plays exchanges through the ordinary
   reducer so a screenshot can be of a conversation in progress. DEBUG
   only.

## Not done

**No screenshot of the investor room or the board room.** Both use the
same `PitchRoomSheet` as the two below and are exercised by the same code
path, but neither is reachable by a headless pass on the committed
fixtures: all three fixtures have `pendingOffer: false` and
`boardPressure: 0`, and a live run that reaches a term sheet either stops
on a critical `DecisionSheet` (which covers the pitch sheet — a sheet
presented from a card under a root sheet never appears) or, with
`-autoAnswer`, has the offer accepted out from under the button before it
can open. A fixture with a pending term sheet would fix this in one line
of `ReleaseFixtureGenerator`, but regenerating fixtures is a
byte-identity risk I did not want to take in a lane branch — see
follow-ups.

## Follow-ups (things I did not do because they are not mine)

- A fixture with a pending term sheet and a board under pressure would
  make the investor and board rooms photographable. `ReleaseFixtureGenerator`
  is in the engine's test target; adding a brief there is a test change,
  which the repo rule forbids this round.
- `GameEvent.severity` could grade `.pitchOpened` `.quiet` rather than
  `.info` if the PM wants the feed quieter; the switch has no marked
  region.
- The four counterparts each have four wants; a fifth "want" per
  counterpart tied to the founder's traits (a Hustler journalist wanting
  a number, say) would be cheap content work on `Pitches.json` alone.
- `Networking.swift`'s marked region was left empty — the room did not
  need a new `ContactArchetype`.
