# M4 — Leagues and challenges

Branch `m4-leagues`, from `scaffold-10`. No merge, no push.

## What it is

A weekly league on one seed, with four rungs and promotion and
relegation read off the client; and *Beat my company*, a link that
carries a seed, a year and a score so two people can run the same
company and compare the two years side by side.

Everything is derived, nothing is served. A week's world is a function
of the week number the way the daily's is of the day; a tier's table is
the tier's own recurring Game Center board (or, signed out, the week's
ghost field); promotion is arithmetic on that table.

## The engine

`Packages/TycoonEngine/Sources/TycoonEngine/League.swift` — all pure,
all prefixed `League`:

- `LeagueWeek` — the week's seed, origin and difficulty. Weeks run
  **Monday to Sunday UTC**; `DailyChallenge.epoch` (2026-01-01) is a
  Thursday, so the week index is `floor((day + 3) / 7)` and week 1 opens
  Monday 5 January 2026. Seed derivation has the daily's and the
  season's shape (one discarded draw, then the seed), keyed
  `0x1EA6_0E5E_ED00_0001`. Horizon is `GameState.daysPerYear`, the
  daily's rule.
- `LeagueTier` — `bronze`, `silver`, `gold`, `founders`; `Comparable`,
  with `promoted`/`relegated` neighbours.
- `LeagueRules` — the field, the bands, and `outcome(rank:fieldSize:)`.
- `LeagueTable` — `standings(you:score:others:)`, `rank(inStandings:)`,
  `placeText(rank:fieldSize:)`.
- `LeagueRecord` — the ledger's memory: tier, last settled week, last
  rank and field, last outcome, best tier, weeks played.
  `settling(week:rank:fieldSize:)` is the whole promotion machine.
- `LeagueOutcome` — `promoted` / `held` / `relegated` / `unplaced`.
- `LeagueChallenge` — the *Beat my company* payload, with `encoded` and
  `decode(_:)`.

`RunMode.league(week: Int)` in M4's marker, plus `isLeague` and
`leagueWeek`. The one exhaustive switch over `RunMode` in the repo is
`isRanked`, which now reads `case .standard, .daily, .season, .league:
true` — a league week is ranked exactly the way the daily and the season
are.

`LegacyLedger.league: LeagueRecord?` in M4's three marked regions
(field, coding key, decoder). Absent on every old ledger and decoded as
`nil`, which the app reads as `LeagueRecord.starting` — a new bronze
player who has never played. The synthesized encoder uses
`encodeIfPresent` for an Optional, so a ledger that has never touched
the league writes exactly the bytes it wrote before.

## The tier and promotion rules

- Four rungs. Everybody starts in **bronze**.
- The field is meant to be twenty (`LeagueRules.fieldSize`). The table is
  read against whoever actually turned up, so a thin week still settles.
- **Top four go up, bottom four go down.** In a field smaller than nine
  the two bands shrink to `(field − 1) / 2` each, so nobody is ever
  promoted and relegated by the same result. `founders` cannot climb and
  `bronze` cannot fall; the outcome still reads `promoted`/`relegated`
  and the card says "there is nothing above it" / "you cannot fall
  further".
- **When it settles:** the first time the player opens the League screen
  in a week later than the one they last finished. `settleLeague(before:)`
  reads that week's table (the previous occurrence of the tier's board,
  or the ghost field), takes the rank, moves the tier once, marks the
  week settled so it can never settle twice, and writes the rank back
  into the league ledger's entry. A week that cannot be placed at all —
  signed out, nothing in the ghost cache — is marked settled as
  `unplaced` and the tier holds.
- A tie puts the player above the row they tied with: the table is theirs
  to read, and a tie is not a relegation.

## The challenge payload

Two forms of the same five fields — marker, seed code, year grid in
letters, score, challenger's name.

**The line** (`LeagueChallenge.encoded`), pipe-separated, the name last
so anything odd in it cannot break the fields before it:

    BEAT1|SS1-386GF6N3-DA8665M5-8|QQUULDDULUUCRUUUDDLUUUQ|312400|Mira Okafor

**The link** (`GameSession.challengeURL(for:)`), on the scheme the app
already registers (`project.yml` needed no change):

    startupstudio://beat/<seed code>?g=<letters>&s=<score>&n=<name>

One scheme, two hosts: `seed` founds the company, `beat` founds it *and*
carries the year to compare against. `handleOpenURL` tries `beat` first
and parks the challenge alone — parking the code as well would open the
*From a code* sheet over the challenge card.

The grid travels as **letters**, not squares (M4's marked region in
`YearGrid`): `U` up, `D` down, `L` a launch, `C` a crash, `R` a round,
`Q` quiet. Emoji do not survive URLs, keyboards and a copy that strips
them; the squares are only ever what gets drawn.

Names are cleaned on the way in and out: no separators, no newlines, 24
characters, never empty (`LeagueChallenge.cleaned`).

**Playing one** is a custom company on that seed, in an ordinary save
slot — which is the point: the challenge you took on is a company you
keep. The seed is recorded in the league's own `Challenges` store; when a
run on that seed stops (an ending, or day 364), the front door reads both
years off the save and shows the comparison once.

## Game Center

Four new recurring boards, one per rung, **weekly from Monday 00:00 UTC**
so an occurrence is exactly a league week:

    com.alpsenel.startupstudio.lb.league.bronze
    com.alpsenel.startupstudio.lb.league.silver
    com.alpsenel.startupstudio.lb.league.gold
    com.alpsenel.startupstudio.lb.league.founders

A player posts to one board only — the rung their ledger says they are on
— and the app reads that same board back to build the table
(`LiveLeagueBoards`, `GKLeaderboard.loadPreviousOccurrence` for a week
that has closed). `docs/release/game-center-ids.md` has the rows and a
section on the rules and the challenge decision.

### The GameKit challenge API: what I did and why

**The share card, not a Game Center challenge.** The iOS 26.5 SDK is
present and `GKChallengeDefinition` compiles, but it is a
*developer-defined* challenge created in App Store Connect — the
client-side composer (`challengeComposeController`) is deprecated as of
iOS 26 with the note "Replaced by developer defined challenges", and
there is no API on this SDK that lets a player issue an arbitrary "beat
my score on this seed" challenge. So *Beat my company* is the link and
the share card, which is the brief's stated fallback. If the owner later
creates a challenge definition against the league boards, the scores the
game already submits feed it with no code change; nothing in the app
depends on one existing.

## Deviations and judgement calls

1. **Two GameKit files.** `LiveGameCenter.swift` says it is "the only
   file in the app that imports GameKit". `LeagueBoards.swift` is the
   second. Reading a board is a different question from reporting to one,
   and adding a read method to `GameCenterClient` would have forced the
   queueing and no-op clients (files I do not own) to answer a question
   they have no business answering. The read seam is its own protocol
   with its own no-op.
2. **`UnlockGate.swift`** — one clause: `|| mode.isLeague`, so the
   paywall does not stand in front of a league week, exactly as it does
   not for the daily, a scenario or a season. The file is owned by no
   lane and has no markers; without the clause the feature is broken for
   an unentitled player.
3. **Two stored properties on `GameSession`** (`league`,
   `pendingChallenge`), in the file's "Iteration 7 — one stored property
   per lane" section, which exists precisely so a lane does not have to
   invent one. They are inside fresh `// MARK: Iteration 10 — M4` markers
   so M5 can slot in beside them.
4. **No `Route` case, no tab.** The League lives at the front door like
   the daily and the season, so `AppRouter`'s M4 markers are left empty
   and `-autoLeague` needs no `-autoTab`.
5. **No new `GameAction`, `GameEvent` or reducer handler.** A league week
   is a run in a mode; nothing about it is an action inside a run, so
   those M4 markers stay empty.
6. **No new balance values**, so no `Balance.json` key and nothing to
   read 1.0 at its default.
7. **No new draws** from `rng` or `worldRNG`. The week's seed is a
   private `SeededRNG` off the week number; the demo field's numbers are
   a private stream off the week's seed, in DEBUG only.
8. **`DebugLaunch.isHeadlessPass`** — `-autoLeague` joins `-autoDaily`,
   `-autoScenario` and `-autoRoom` in the guard that keeps the front door
   alive alongside `-autoSpeed`. Without it the flag was silently useless:
   a headless pass skips the door, so the League row's own launch path
   never ran and a generated company played instead. One line, outside my
   markers, in the same shape as the daily's.
9. **`observeEvents("league")`** in `playLeague`, dropped in
   `leagueRunChanged`. An ending before day 364 stops the run on the tick
   that raises it and the autosave that follows is not guaranteed to
   carry it — the daily hit this and hangs the same check off the event
   fan-out (`GameSession+GameCenter.swift`). The league uses the
   documented per-lane fan-out key rather than editing that file.

## Follow-ups

- **`CloudGhostStore.isEnabled` is still `false`** (no iCloud container
  on the App ID), so a real tier's ghost field is only ever this phone's
  own past weeks until it is flipped. The league's keys are already in
  the same record type, so flipping it turns the field on for both the
  daily and the league at once.
- **The tier's board is the only place a real field comes from.** Nothing
  can be verified on a simulator with no Game Center account; the ghost
  fallback and the `demo` flag are what the screenshots show.
- **A challenge definition** (`GKChallengeDefinition`) attached to the
  league boards would light up Game Center's own challenge UI at no code
  cost. Owner-side, in App Store Connect.
- **`GameSession.challengeResult()` scans the save slots** for a finished
  run on an accepted seed. That is the only hook I could reach without
  editing `GameSession+Legacy.swift`, which I do not own; a one-line call
  from `recordEnding` would be tidier and would catch a challenge run
  that was deleted before the player came back to the door.
- The League screen is a sheet, like the season's. If the PM wants a
  full-screen room later, `LeagueScreen` is already the content view.
