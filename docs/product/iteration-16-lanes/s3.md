# S3 — product names

Branch `s3-names` from `scaffold-16` (c88e04d). Simulator `ws-l3`.

The owner's complaint: building the same kind of product again suggests
the same name. The cause was in `NewProductFlow.suggestion`: 12 stems ×
4 suffixes, picked by `(topicID.count + typeID.count) % 4`. The same type
and topic always came out as the same word (fitness × mobile app was
always *FitSnap*).

## What shipped

**Content: `ProductNames.json`** in `TycoonContent/Resources`. It is loaded by
`ContentCatalog.loadBundled()` through `decodeResourceIfPresent`, the same way
`Pitches` and `Feed` are loaded, into `ContentCatalog.productNames:
ProductNamePools?`. `productNamePools` falls back to the old hard-coded stems
when the file is missing. The file holds:
- 12 stems per topic (12 topics)
- 12 suffixes per product type (6 types)
- 80 standalone words, 32 prefixes and 12 tails
- nine weighted patterns: `{stem}{suffix}` 5, `{prefix}{stem}` 3,
  `{stem}{suffix} {tail}` 2, `{word}{suffix}` 2, `{word} {word}` 2,
  `{stem} {tail}`, `{word} {tail}`, `{prefix}{suffix}` and `{word} {stem}` 1 each
- three sequel tails
- 104 banned real names. A name is refused if it matches one whole, or if any
  of its space-separated words does.

**Generator: `ProductNameGenerator.suggest(typeID:topicID:seed:taken:count:pools:topicName:)`**
(in TycoonContent, `ProductNamePools.swift`):
- It is a pure function with its own SplitMix64 stream.
- It returns `count` distinct names, never taken, banned or repeating a
  fragment, and at most 20 characters.
- Names that carry a topic stem come first, because the first name pre-fills
  the field.
- If random draws cannot find enough free names, it walks stem × suffix × tail
  in order.
- Names are compared by `key()` (lowercase letters and digits only), so *Fit
  Track* and *FitTrack* count as one name.

**Engine (reads only, `ProductNames.swift`):**
- `productNamesInUse`: the player's products (live, in development, retired)
  plus every rival shelf.
- `productNameClaim(_:)`: `.yours` or `.rival(studio:product:)`.
- `productNameSeed(reroll:)`: a hash of `seed`, `products.count` and the reroll
  index.
- `productNameSuggestions(…)` and `sequelNameSuggestions(parentID:…)`.

Nothing here draws from `rng` or `worldRNG`, sends an action or stores a field.

**App (`NewProductFlow` inside `// MARK: S3` pairs, plus a new
`ProductNameViews.swift`):**
- The name card shows three pixel chips (a `PixelPanelBorder` frame, paper
  fill, and the accent colour on the chip that matches the field) and a
  pixel *Shuffle* die.
- Shuffle adds 1 to the reroll index, and the batch it replaces is kept out of
  the next one, so it always brings three new names.
- A typed name is never overwritten; tapping a chip makes the field a
  suggestion again.
- The Hall of Fame (`session.ledger.hall`) is kept out of the suggestions.
- A name already used in the run is refused inline, and Start is turned off:
  *You already have a Round 6.* for the player's own products, *<Studio>
  already sells a <name>.* for a rival's.
- The v2 path, from the product page and from the "v2 of…" chips, offers
  *X 2 / X II / X Next* first. It offers *X v2* instead of *X 2* when the name
  already ends in a digit, so *Round 6* gets *Round 6 v2*, not *Round 6 2*. A
  parent that is itself a successor steps up a generation (*X 2 → X 3*).
  Shuffle leaves the sequels and draws from the generator.
- `ProductsScreen` gains one marked line for the debug route.

## Measurements

These come from a scratch SwiftPM runner outside the repo (not a test), run
against the bundled fixtures:

| | campus day 900 | studio day 400 |
|---|---|---|
| names in use | 62 (54 products, 8 rival) | 31 (17 + 14) |
| fitness × mobile app, 1,000 rerolls chained as the flow chains them | 3,000 names, **1,894 distinct**, every batch full, no two adjacent batches share a name | 3,000 names, **1,862 distinct** |
| raw collisions (generator with `taken = []`, all 72 type × topic × 100 rerolls × 3) against the run's names | **0 of 21,600 (0.000 %)** | 0 of 21,600 |
| names that got past the exclusion filter | 0 | 0 |

- **Reachable names per type × topic:** 9,642 distinct for fitness × mobile
  app and 9,569 for dating × game, over 20,000 seeds.
- **Banned names in that space:** none.
- **Collision rate:** the campus fixture has **54** products (all named
  *Round N* by the bots), not the 36 the brief says. Collisions are zero
  because the bots' *Round N* names and the rivals' two-word `productWords`
  names share no fragments with the new pools. The exclusion is still wired,
  and the runner checked it on every batch.

## Rules

- **Identity at the default / no draws:** the flow is app-side, and the
  engine additions only read. The bots still name products *Round N*
  (`InvestorBots`) and never call the flow. Engine **943**, content **52**,
  save **34** and PixelKit **336** all pass with those exact counts. The app
  reports `Executed 385 tests, with 0 failures`. The fixtures do not move.
- **Rivals left alone.** `RivalSystem.productName` draws exactly two
  `worldRNG` picks from `productWords`, and the resulting name is stored in
  `RivalProduct.name`, which the byte-identical fixtures encode. Any other name
  would change those bytes even if the draw count stayed the same, so a
  byte-identical seam is impossible. Rival names are only excluded from the
  player's suggestions and refused when typed.
- **Old saves load:** nothing new is stored.
- **No new tests.** **Re-pins: none.** No resource list or count is pinned
  (`.process("Resources")` picks up the new file automatically, and
  `ContentCatalogTests` only checks `Names.json` pools with `>=`).
- **Pixel, not SF:** the chips and the die use the pixel frame. The die glyph
  is an SF symbol inside a pixel tile, as `PixelIconTile` does.

## Deviations and follow-ups

- **Rivals** still name from `productWords` (see Rules). Giving them the
  generator would be a deliberate fixture re-pin, and the owner should decide
  that.
- **The Hall of Fame** is excluded from suggestions but not refused when
  typed. It belongs to earlier companies, and the brief refuses only names
  "taken in the run".
- **The engine itself does not refuse a duplicate name** in `.startProduct`.
  The guard is app-side, so no bot path changes. An engine refusal would be a
  behaviour change for bots and fixtures.
- The four new strings (the two refusals, *Name it …*, *Shuffle names*) need
  `make strings` at the round's wrap.
- K2's `NewProductFlow.lifecycleName` stays as the fallback when every sequel
  name is taken. K2's `k2-replace` and `k2-launch` look up *"\(parent) v2"* on
  an engine-seeded build, which is unaffected.
