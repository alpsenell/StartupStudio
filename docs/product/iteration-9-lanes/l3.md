# L3 — Children who grow up, and remember

Branch `l3-children`, off `scaffold-9`. No merge, no push.

## What shipped

**Five ages, derived not stored.** `ChildStage` (`baby → toddler → school →
teen → grown`) is computed from `bornDay` and the day, so an old save's
children have an age the moment it loads and nothing migrates.
`Child.stage(on:balance:)`, `ageLabel`, `bornLabel`, `bondLabel`,
`latestMemories` and `isInterning(on:)` live in the new
`Packages/TycoonEngine/Sources/TycoonEngine/Childhood.swift`, next to
`ChildMemoryKind`, the tag vocabulary the ledger and the dynasty share.

**Bond.** `Child.bond` (0…100, default 50) plus `lastTimeDay`,
`internEmployeeID`, `internUntilDay` and `internSummers`, all added to the
hand-written `Child` Codable as decode-if-present / encode-only-when-
non-default, so a child written before this round encodes exactly the bytes
it always did.

**`ChildhoodSystem`** (`Systems/ChildhoodSystem.swift`), registered in the
L3 region of `Reducer.systems`. Its first line returns for a founder with
no children, so every pacing bot and every balance sweep is untouched. It
draws from no RNG stream at all. Each day it:

- turns over any stage that changed overnight, writes a `grewUp` memory,
  posts the line to the child's phone thread, and schedules that stage's
  `followUpOnly` beat with the child's id;
- reads *yesterday's* `eventLog` for the things a child would still be
  talking about — a launch reviewed at 75+, a burnout, a hospital stay, an
  eviction, a chapter, an IPO, a sale, a friend's wedding attended — plus
  `state.life.sabbatical` starting (L6's slot, read as "is it set today");
- resolves the family beats answered yesterday into bond, and writes the
  birthday memory either way;
- ends finished summers and slides the bond of any child who has been
  ignored past the grace window.

**An evening.** `.spendTimeWithChild(childID:)` in the L3 action region:
one evening, a stage-appropriate vignette (five of them, one per age), bond
+9, mood +6, relationships +5, a memory, a line on the thread.
`ChildhoodSystem.eveningRefusal` is public and the sheet shows exactly what
the engine enforces on the button.

**The summer.** `.hireChildIntern(childID:)` puts a teenager with bond ≥ 60
on the roster for eight weeks in summer only (the calendar knows months):
no salary, a small skill sheet, morale 85, `founderBond` seeded from the
child's bond. The employee's id and face come from a *local* `SeededRNG`
seeded off the child's own `appearanceSeed` — deterministic, and it never
touches `rng`, `worldRNG` or `socialRNG`. `.endChildInternship(childID:)`
ends it early for −15 bond and a memory that says so.

**Four new `kid_*` beats**, appended to the very end of `LifeEvents.json`
and nowhere else: `kid_first_sentence`, `kid_first_day`, `kid_teen_door`,
`kid_moves_out`. All four are `followUpOnly`, so they are never in the
weighted roll and appending them moves no existing run's `rng` stream;
`ChildhoodSystem` schedules them at the stage transition with the child's
id, so `{child}` fills with the right name.

**Dynasty.** `LegacyChild` gained `bond`, `memories` and `internSummers`
with a hand-written Codable on the same encode-only-when-non-default rule,
and `LegacyLedger.record` fills them. `Successors.Upbringing` reads the
ledger: two hard years → Grumbler, two or more launch nights → Speedster
(and a hacker), a summer at the studio → Mentor (and a hustler), three
kept evenings or bond ≥ 75 → Loyalist, two missed birthdays → Loner. The
successor row now reads "Child of Mira Okafor, who ran Northgate. Grew up
through two launch nights and a summer at the studio. Reads as: Speedster,
Mentor." A child from a run recorded before this round has an empty ledger
and falls back to the appearance-seed archetype the dynasty always used.

**PixelKit.** `HomeOccupants.Child.stage: ChildStageStyle` (raw values
mirror the engine's `ChildStage`, defaulting to `.school` so the existing
picture is unchanged), and a new `HomeChildArt.swift` with a stubby 8×11
toddler, a 10×18 teenager, widened hair overlays, and
`SpriteLibrary.child(appearance:stage:)` mapping the five ages onto baby /
toddler / the original chibi / teen / the standing adult. Palette-only: the
grids use characters the shared `personPalette` already resolves, and the
PixelKit suite passes unchanged (336) — **no baseline needed re-pinning.**

**App.** `FamilyCard` draws each child as a `ChildRow`: the sprite at their
real size, the stage, the bond bar, the last two memories, and a chevron
into the ledger. `ChildrenScreen` (pushed, `Route.children`) lists them all;
`ChildSheet` shows the full ledger with the game date of each entry and the
two actions with their consequences on the buttons.

## Numbers I chose

| | |
|---|---|
| Stage thresholds (days since birth) | baby < 180, toddler < 540, school < 1100, teen < 1800, grown ≥ 1800 |
| Bond at birth | 50 (also the Codable's "nothing to write" value) |
| Grace before silence costs | 14 days |
| Decay past the grace window | 0.08 / day (≈ −29 over a game year of nothing) |
| An evening | +9 bond, cooldown 5 days |
| A family-time weekend | +2 bond per child |
| Birthday kept / missed | +10 / −14 |
| Any other `kid_*` beat, warm / cold | +6 / −6 |
| A burnout, hospital stay or eviction | −4 |
| A launch reviewed 75+ | +2 |
| Memory cap | 12, oldest dropped |
| Intern gate | teen, bond ≥ 60, summer only |
| Intern summer | 8 weeks, no salary, +6 at the start and +6 at the end |
| Ending it early | −15 bond |
| Intern skills | coding 22 / design 18 / marketing 12 |

All of it lives in `ChildhoodBalance` (`BalanceConfig+Childhood.swift`),
reached through a computed `balance.childhood`. Identity at the default is
trivially true: nothing here is a multiplier on an existing number, and
none of it runs at all in a childless house.

## Deviations, and why

1. **`balance.childhood` is a computed default, not a `Balance.json`
   block.** Adding a stored property to `BalanceConfig` would mean
   hand-writing that whole struct's Codable, which is a shared file and a
   large blast radius for numbers no balance sweep wants. The struct is
   public and the accessor is one line to promote later.

2. **Bond from an answered beat is read off the log, not hooked into
   `NarrativeSystem`.** That file's hooks belong to L1 this round. The cost:
   `.narrativeResolved` does not carry a `childID`, so a beat answered in a
   two-child house moves both children's bond. The birthday — the one beat
   that is always about one child — reads the same either way while the
   diary only has one birthday due at a time. **Follow-up for whoever owns
   `NarrativeSystem` next:** put `pending.childID` on `.narrativeResolved`
   (or call `ChildhoodSystem.kidBeatResolved(eventID:childID:missed:…)`
   from `resolve`) and this becomes exact.

3. **Memories land one day late.** Systems run before `Reducer.tick` logs
   the day's events, so `ChildhoodSystem` reads `state.day - 1`. That
   needed no cursor field on the state and sees each day exactly once.

4. **"An award won" is not a memory.** Awards are judged app-side
   (`AwardsJudge`) and raise no `GameEvent`, so the engine cannot see one.
   I used `.chapterReached`, `.wentPublic` and `.companySold` in its place.
   **Follow-up:** if awards ever raise an event, add one `case` to
   `ChildhoodSystem.trigger`.

5. **The pixel home still draws one size.** `HomeSceneComposer` and
   `HomeSpriteLibrary` belong to L7, and my brief says to write a room
   change as a follow-up rather than edit them. The four sizes ship and are
   visible on the Family card, the kids screen and the child sheet.
   **Follow-up for L7, two lines:** carry `HomeOccupants.Child.stage`
   through the app's occupants builder, and in `HomeSceneComposer`'s child
   loop call `SpriteLibrary.child(appearance:stage:)` instead of
   `SpriteLibrary.child(appearance:)` — the new overload already exists and
   `.school` reproduces today's sprite byte for byte. A teen's desk in the
   house / penthouse is a `HomeRoomBuilder` anchor, also L7's.

6. **Two small edits outside a marker region**, both additive and both
   directed by the brief:
   - `Legacy.swift`: `LegacyChild` gained three fields and a hand-written
     Codable, and `record` fills them. L2's marked region in that file is
     untouched.
   - `App/Sources/ReleaseFixtures.swift`: a new `laneFixtures` array
     beside `names`, and one `||` in `data(named:)`. `names` itself is
     untouched, because `ReleasePlumbingTests` pins it at exactly the
     three store-listing fixtures and my debug save is not one of those.

7. **`-autoFamily` became a bundled fixture instead.** There is no seam in
   a file I own where a headless pass could construct a family, so I
   generated `App/Resources/Fixtures/l3-family-day900.json` (the campus
   fixture, married, in a house, with a teenager and a toddler and their
   ledgers) and reached it with the existing `-autoFixture`. My own debug
   flag is `-autoChild`, in the L3 markers of `DebugLaunch.swift`: it opens
   the first child's sheet as soon as the kids screen appears, because
   `simctl` cannot tap. `-autoRoute children` is in the same file's L3
   markers; the push itself is consumed by `ChildrenLink`, a zero-height
   view in my own folder placed in my `LifeScreen` marker, so the Life
   tab's shared `consumeRoute` did not have to grow an arm.

8. **One expectation re-pinned.** `ContentVarietyTests`'s "every follow-up
   resolves, and follow-up-only events are reachable" unions the two ids
   `FamilyCalendar` schedules itself; it now also unions
   `ChildhoodSystem.stageBeatIDs`, the four this system schedules. Same
   test, same count (943 → 943), one extra `formUnion` line. **No tests
   were added.**
