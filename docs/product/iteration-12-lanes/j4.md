# J4 — The house field

*Iteration 12. Branch `j4-field`, cut from `scaffold-12`. No merge, no push.*

Nineteen named house founders play every league week's seed and every
daily day's, with the bots the balance suites already measure the economy
with. The league table has twenty rows on the day anyone installs, the
four rivals a daily or league company is founded against are people with
a way of playing, and the result card says who finished directly above
you and how they play: *"Directly above you: Nina Achebe. You came 10th
of 20. Blitz — crunches, hires to the ceiling, pays over the odds —
finished $4,117 ahead."*

## What I built

### The engine package: `TycoonBots`

- **A new library target**, `TycoonBots`, in
  `Packages/TycoonEngine/Package.swift`, depending on `TycoonEngine` and
  `TycoonContent`, and a product the app links (`project.yml`).
- **`SimRunner.swift`, `PacingBots.swift`, `InvestorBots.swift` moved**
  (`git mv`) from `Tests/TycoonEngineTests` into `Sources/TycoonBots`.
  The only changes are access control:
  - `public` on `BotPolicy`, `SimRunner`, `SimRunner.Result` and every
    field on it, `BotHelp`, and all ten bots;
  - explicit `public init`s where a memberwise init had been doing the
    work across the old module boundary — `CrunchHireBot`, `InvestorBot`,
    `AcquirerBot`, `BuybackBot`, and `init() {}` on the six bots without
    parameters. The parameter lists and defaults are the memberwise ones,
    so every existing call site reads the same.
- **One addition to `SimRunner`** (J4 markers):
  `run(from:days:bot:balance:content:)`, the same loop started from a
  state the caller founded. `run(days:seed:…)` founds its garage state
  and calls it, so every bot run is byte-for-byte the loop it was.
- **The test target** depends on `TycoonBots` and gains `import
  TycoonBots` in the 18 files that use the bots. No other test edits and
  no new tests; 943 still pass.
- **`Sources/TycoonBots/HouseField.swift`** — the pure half of the
  feature, so the app and the Mac check run the same code:
  - `HouseFieldStrategy` is twelve ways of playing, each one of the
    harness's bots, with a label and a clause. Grinder is
    `ContractGrinderBot`, Saver `BalancedBot`, Solo `SoloSlowBot`, Crunch
    boss `NeglectfulBot`, Blitz `CrunchHireBot` and Platform
    `SaaSBuilderBot`. Funded, Deaf ear, Bootstrapper and Coaster are
    `InvestorBot` and its three variants; Seller is `AcquirerBot` and
    Buyback is `BuybackBot`.
  - `HouseFieldFounder` has a name, a strategy, and three twists that
    keep two founders with one strategy from being one founder twice:
    topic rotation, a weekend a month, and the hiring runway. Its face is
    an FNV hash of its id, not a draw. `bot()` builds the harness bot
    wrapped in `HouseFieldBot`, which applies the two twists to the
    bot's own actions.
  - `HouseFieldRoster` holds four tables of 19 (`fieldSize =
    LeagueRules.fieldSize − 1`) and the daily's cross-section of 19,
    drawn from the same people, so the house is one cast. `version`
    lives in every id (`bronze-03.v1`), so a cache filed under an older
    roster is played again rather than shown.
  - `HouseFieldSetup` and `HouseFieldRun.play` found the company the
    player founds, then run the bot to the horizon through
    `SimRunner.run(from:)`. The company has the same seed, origin,
    difficulty, founder (flat skills, the same appearance seed), company
    name and mode, with the balance adjusted for difficulty and then
    `GameRules.standard`, in `GameEngine.newGame`'s own order. The run
    has no ghosts in it, so every phone founds the same world. The result
    is scored with `founderNetWorth`, the number the league and the daily
    score the player on.

### The app

- **`Leagues/HouseFieldRunner.swift`** is an actor, `HouseFieldRunner.shared`:
  - It shares one run between callers asking for the same key, and plays
    fields one after another.
  - The bots run on a utility dispatch queue with `concurrentPerform`
    across the cores, never on the cooperative pool.
  - It never touches `GameSession`; results go back to the main actor.
  - Every field logs one line through `os.Logger` (category
    `HouseField`), in Release too. That is how the timing check below was
    read.
- **`Leagues/GameSession+HouseField.swift`**:
  - `ensureHouseField(week:tier:)` and `ensureHouseField(daily:)`. They
    play only when the cache lacks a founder of the current roster, then
    file each result as an ordinary `GhostLog` in one write, under
    `LeagueGhostKey` or the daily's day number.
  - Table helpers: `houseFieldFill` (house founders to make twenty,
    spread evenly down the house's own table when real players take some
    seats), `houseFieldLines` (name → "Grinder — contracts only, never
    hired") and `houseFieldRealPlayers`.
  - `houseFieldAbove(forDaily:)`.
  - The DEBUG `-autoHouseField` filer.
- **`Leagues/HouseFieldAbove.swift`** holds `HouseFieldAbove`, which reads
  the row directly above the player off a sorted table, and
  `HouseFieldAboveLine`, the line both result cards draw.
- **When it plays** (J4 markers in the two refreshes the front door
  already calls on every open):
  - `refreshGhosts(forDailyDay:)` plays yesterday's seed (the four rivals
    today's company is founded against, through the untouched
    `ghostScripts(forDailyDay:)`) and then today's (the result card's
    field).
  - `refreshLeagueGhosts(week:tier:)` plays this week's tier.
  - Cloud first, house second, so real players come first once
    `CloudGhostStore.isEnabled` flips.
- **`GameSession+League.swift`** (J4 markers):
  - `leagueStandings` awaits the house for the tier's week first, which
    is also what settles a week nobody else turned up for.
  - On the board path it adds house founders to the board's real players
    to make twenty.
  - On the ghost path, the real players this phone has seen come first,
    then the house.
  - Three new `LeagueView.Source` cases say which of these the table is:
    `.house`, `.boardAndHouse`, `.ghostsAndHouse`.
  - `LeagueView.houseLines` carries how each house founder plays.
  - `settleLeague` is unchanged: its `fieldSize = max(standings.count,
    rank)` is now 20, so `LeagueRules.outcome` promotes four and
    relegates four instead of returning `.held` for a field of one.
- **`GhostStore.swift`** (J4 markers):
  - `GhostLog.houseFounderID: String? = nil`. It is Optional, so the
    synthesized coding decodes it if present and encodes it only when
    set. Old caches and every real log read and write the bytes they did.
  - `LocalGhostStore.save(all:)` writes a field in one pass per day.
- **Cards** (J4 markers):
  - `LeagueResultCard` and `DailyResultCard` gain an optional `above`,
    drawn under the result's lines.
  - `LeagueRow` shows the house founder's way of playing under the name,
    and in its accessibility label.
  - `LeagueTableView` and `LeagueScreen` pass it through.
  - `DailySheet` passes `above` to the card.
  - `TitleScreen` builds the daily sheet through a J4 helper,
    `houseFieldDailySheet(_:)`, and calls the `-autoHouseField` filer
    from its launch-flag block.
- **`LeagueDemoField.swift`**: the twelve random names are gone.
  `-autoLeague demo` now starts the house field for the week, which the
  table would play when it opens anyway.

## The rosters

| Tier | Who (19 each) |
|---|---|
| Bronze | 7 Solo, 2 Grinder, 5 Saver, 5 Crunch boss |
| Silver | 15 Blitz (runways 9/12/16/20/26), 4 Platform |
| Gold | Seller, Deaf ear, Bootstrapper, Buyback, Funded — runway variants |
| Founders | The best variant of each, by pooled rank: Seller, Bootstrapper, Buyback, Deaf ear, Funded, the best Solo, the best Blitz |
| Daily | 5 Bronze, 5 Silver, 5 Gold and 4 Founders people, chosen so no two play identically |

## Check 1 — the spread (Mac, release, the eight weeks to 10 Sep 2026)

A scratch SwiftPM executable outside the repo depends on the worktree's
`TycoonBots`. It plays 230 variants of the twelve strategies over league
weeks 29–36 (1,840 runs in 5.6 s) and ranks them pooled, then plays the
final rosters as tables. It is not a test and not in the repo.

The rosters were chosen so that fourth place — the promotion line — gets
harder to reach rung by rung. The share of all 230 variants that beat
each table's fourth, averaged over the eight weeks, was 0.31 for Bronze,
0.27 for Silver, 0.18 for Gold and 0.14 for Founders. That was measured
on the proposal; I then hand-edited Bronze and Founders, as below.
(Bronze swaps three Savers for Neglectful variants, so the spec's three
families are all there. Founders swaps in the best Blitz.)

**Reading.** It is not too soft. Only about a quarter to a third of the
rung above's own founders would win promotion from the rung below in a
given week. A player who plays like the house's middle climbs slowly,
and nobody reaches Founders in three weeks without finishing top four
three weeks running.

It is not too hard either. Every table has a $60k–$200k gap between
fourth and sixteenth on ordinary weeks, and promotion bars in reach of a
company that ships and survives.

**How it fails, measured:**

1. **Hard weeks empty the funded tables.** On weeks 34–36 (spin-out,
   hard) every Gold founder and 18–19 of the Founders go bankrupt. The
   tables collapse to $24k–$30k with ties, so a player who merely
   survives such a week tops Gold.
2. **No house founder ever filed an IPO.** In 1,840 pool runs there were
   0 IPOs, 2 acquisitions and 3 oustings. The spec's IPO worry did not
   happen; the risk that did show up is the bankruptcy cluster above.
3. **Identical scores.** Investor variants that die before their first
   term sheet play identically, which gives 10–14 tied pairs per
   Gold/Founders table on the hard weeks. The table breaks ties by name.

The gate was "nineteen runs over about ten seconds, cut to nine". It is
nowhere near, so **the field stays at nineteen**. The cut would be one
constant, `HouseFieldRoster.fieldSize`, which every table and the daily
read.

This is not measured on a phone. The owner's device should be about the
simulator's Release number; the Logger line reads the same there, in
Console, under the `HouseField` category.

## The rules

- **Identity at the default.** No engine source changed: not the
  balance, not `GameState`, no `rng` or `worldRNG` draw. The bots run in
  their own `GameState`s, off the main actor. The player's run meets the
  house only through the ghost path that already existed (founding
  rivals from `GhostScript`s draws nothing). The fixtures and pacing
  bots are untouched, and the engine suite passes at 943.
- **Old saves and the ghost cache load.** `houseFounderID` is Optional
  and encoded only when set. No save or ledger type changed.
- **No new tests.** No test file, function or snapshot was added. The
  engine test target changed only by losing three files to the library
  and gaining 18 `import TycoonBots` lines.
- **Markers.** Every edit to a shared file is between J4 markers. The
  marked edits in files outside the scaffold's list are `TitleScreen`,
  `DailyCards`, `GhostStore`, `GameSession+Ghosts`,
  `GameSession+League`, `LeagueCards` and `SimRunner`. The new files are
  all `HouseField…`.

## Deviations and judgement calls

1. **The roster lives in `TycoonBots`, not in `App/Sources/Leagues`.**
   The Mac check had to run exactly what the phone runs. The app keeps
   the runner, the cache and the UI.
2. **The house plays nineteen per tier, and only the tier asked for.**
   Each tier's table needs nineteen others, and "cut to nine" is about a
   single field. A player's front door plays their own tier's week,
   yesterday's daily and today's daily. `leagueStandings` plays last
   week's tier if settlement needs it and it is missing.
3. **The daily's four rivals are still yesterday's best.** The
   ghost-script path reads `day − 1`, and the brief says to read through
   paths that exist. So the house plays yesterday's seed too, if this
   phone lacks it. Rivals on today's own seed would be one line in
   `ghostScripts(forDailyDay:)` (follow-up 3).
4. **A league run is now founded against four house founders from its
   own week** (`leagueGhostScripts` reads this week's tier). Their
   launches replay on the same seed they were played on. This is the
   existing path doing what it always said it did, now with somebody in
   it.
5. **This phone's own ghost is no longer a second row.** Signed out,
   `recordLeagueGhost` files the player under the company's name, and the
   old table showed it beside the player's own "You" row. The J4 ghost
   path drops real logs filed under the player's Game Center name or
   under the week's company name. Other signed-out players found the
   same company name, so they would be dropped too; that only matters
   once the cloud is on (follow-up 2).
6. **Seasons have no house.** The season card has no ghost path to
   read. It is listed as a follow-up rather than invented.
7. **A Release-only compile failure, found and fixed.** The first
   Release build failed with "the compiler is unable to type-check this
   expression in reasonable time" in `TitleScreen`. The cause was
   `debugFileHouseFieldRun`, which was declared inside `#if DEBUG` but
   called from the front door's unconditional launch-flag block. In
   Release the method did not exist, and inside that long modifier chain
   the compiler reports a missing member as a type-check timeout. The
   method is now declared in every build and only its body is DEBUG.
   Debug builds never showed it, so a lane that only builds Debug would
   not have seen it either.
8. **`-autoHouseField` writes to the simulator's league or daily
   ledger** (DEBUG only), because the result cards read the ledger.
   Launch it without `-autoSpeed`, which skips the front door.

## Follow-ups

1. **Hard weeks.** Give the Gold and Founders tables a survivor or two,
   either an investor variant that never hires before its first sale or
   a `SoloSlow` in each, so a spin-out/hard week is not won by surviving.
   It is one roster edit and a `version` bump.
2. **Cloud identity.** Once `CloudGhostStore.isEnabled` flips, give
   `GhostLog` a player id, so another signed-out player on the same
   seed is not mistaken for this phone's own year (deviation 5).
3. **The daily's rivals on today's seed.** Reading `day` instead of
   `day − 1` in `ghostScripts(forDailyDay:)` would put the four best
   house founders on the same company the player is running. That is a
   product call.
4. **The season.** A season's 28-day seed could get the same field under
   its own key; the season card has no ghost path yet.
5. **Measure on the phone.** The Logger line is there; one front-door
   open on the device gives the real number.
6. **`build-release/`** is the derived-data folder the Release timing
   used. It is not in `.gitignore`, so add it or delete the folder.

## Debug flags

- `-autoHouseField week` (bare: `week`): plays this week's field for the
  player's tier, files a made-up finished year between the house's ninth
  and tenth, and opens the League sheet on the result.
- `-autoHouseField day`: the same for today's daily; opens today's
  result card.
- `-autoLeague demo`: now starts the house field for the week instead of
  writing random names.
- The release-build `HouseField` log line (not a flag): `log show
  --predicate 'category == "HouseField"'` on a simulator or in Console
  on a phone.
